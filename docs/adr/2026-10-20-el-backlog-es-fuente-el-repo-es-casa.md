# El backlog es fuente; el repositorio es casa

## Contexto

El backlog ya está escrito, con su estructura de épicas, features y PBIs. El conocimiento
funcional que cada equipo recopila por su cuenta muchas veces no tiene un work item de origen, o
solo un bug.

## Decisión

El backlog es un diario: qué quisimos hacer, cuándo, por qué, qué se rompió. Sus unidades se
cierran. El conocimiento funcional es un mapa: cómo se comporta hoy el producto. Sus unidades se
consolidan. El mapa vive en el catálogo como fichas; el backlog es una fuente más que lee el
extractor, junto con las sesiones.

El conocimiento no cuelga de un work item: lo cita. Una ficha lleva sus orígenes, que pueden ser
work items o solo la fecha del extracto. Cuando el consolidador encuentra una ficha que contradice
los criterios de un PBI abierto, crea un work item de pregunta: el conocimiento alimenta al
backlog, no al revés.

## Alternativas descartadas

- Guardar el conocimiento funcional en el backlog como work items: se cierran, no se consolidan, y
  obligan a un padre que muchas veces no existe.

## Consecuencias

Una pasada inicial sobre el backlog existente produce las primeras fichas. Las fichas se sirven a
Claude como skills y a las personas como wiki publicada desde el repositorio.
